# Wings of Power student app — plan

Student Flutter app only (`wings_of_power_app`). Visual source: `design/screens/student/**`. Contract: `docs/API.md`, `docs/MODULE_MAP.md`. Decisions: `docs/DECISIONS.md`. Screen list: `docs/SCREEN_INVENTORY.md`.

This plan does not cover `design/screens/game/**` (basketball game show — separate plan) or screens marked junk.

Architecture stays the GetX boilerplate in `.cursor/rules/app.mdc`. New screens are new GetX modules. No second state library, router, or HTTP client.

### How a new feature is added

1. **Module** — `lib/app/modules/<feature>/{bindings,controllers,views}/`
   - `*_binding.dart` extends `Bindings`, `Get.lazyPut<FeatureController>(() => FeatureController())`
   - `*_controller.dart` extends `GetxController`. Repositories come from `Get.find<IFeatureRepository>()`, not `Dio()` in the view
   - `*_view.dart` extends `GetView<FeatureController>`
   - Files `snake_case`, classes `PascalCase`, imports `package:wings_of_power_app/...`
2. **Route** — In `app_routes.dart`, add `Routes.FEATURE = _Paths.FEATURE` and `_Paths.FEATURE = '/feature-name'` (kebab-case). In `app_pages.dart`, add a `GetPage` with `page` and `binding`.
3. **HTTP** — Path strings must already exist in `docs/API.md`. Add a constant on `ApiEndpoint` (base is `AppConfig.domainUrl + /api`). Add `IFeatureRepository` + implementation under `lib/app/data/repositories/`, models under `lib/app/data/models/`, and `Get.lazyPut(..., fenix: true)` in `AppRepositoryBinding`. Map with `ApiClient.handleRequest`.
4. **UI** — `ScreenUtil` (`.w`, `.h`, `.sp`, `.r`), `AppColor`, `AppTheme` text styles, shared widgets from `lib/app/global/`. Images through `Assets.*` in `lib/gen/assets.gen.dart`.
5. **Session** — token and user id through the existing secure-storage helpers. Onboarding-seen and settings cache through Hive.
6. **Mocks** — `AppConfig.useMocks` (added in `T-APP-001`, default `true`). When it is true, the repository returns fixtures from `lib/app/data/mocks/` and does not call the network. Screen tasks name the backend id they wait on (`T-BE-0xx` below). When that backend task exists, the same repository method calls the `ApiEndpoint` and the mock branch comes out. Do not add endpoints that are not in `docs/API.md`.

## 3. Screen order

Runtime order for a new student, from `docs/API.md` “Auth flow” and the inventory. Step labels printed on the PNGs clash (`1/2` on both credentials and nickname, `2/2` on both real name and the hero grid). Each screen shows the label that is on its own PNG. That clash is already in `docs/OPEN_QUESTIONS.md` (designer item 7). These tasks do not renumber the labels.

`Role Selection.png` is the class-code screen. There is no student role picker.

```text
splash → onboarding (first launch only) → welcome
  welcome "Log In" → login
  welcome "Join with Class Code" → class code
      → wrong code | expired code | joined class
      → username/password → nickname → real name
      → POST register (one call with the collected fields)
      → hero grid → hero detail + confirm → hero ready card
      → GET /api/auth/me
           PENDING → account verification (no tab shell)
           ACTIVE  → home
login → 401 stays on the form
login → 422 PENDING → account verification
login → token → home
```

`student.hero_ready` (`Character showing.png`) has no button. Build the card as drawn. Do not add a control that is not on the PNG. Continuing past that card is the open design gap already noted on that inventory row.

After home:

```text
home → story library → story description → chapters
     → reading | listening → chapter complete → chapter quiz → result
     → checkpoint quiz can interrupt reading (quick_checkpoint PNGs)
home Play Game → T-GAME-001 (lock modal or mode select). This plan only draws the banner
home / profile → badges, points, leaderboard, reading progress, power heroes
home Safe Space tile, profile My Reports, settings "I Need Help" → Safe Space
settings gear on profile → settings → change password, log out, how the app works
```
